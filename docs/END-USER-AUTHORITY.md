# Product authority and implementation scope

Governing requirements: [product authority specification](OWNER-DECISION-2026-10-27.md).
Active delivery and remaining work: [authority and parity plan](designs/AUTHORITY-PARITY-2026-10-28.md).

## Product requirements

A full ordinary connection represents the user's approved access to their connected provider accounts. GitHub determines actual permissions, repository protection, environment approvals, billing and provider limits. The user's current explicit instruction overrides their own earlier standing defaults. Disclosure, execution, journaling and independent verification are the shared action contract. Classification describes consequences; it does not add an authority above the user and GitHub.

The product must preserve credential secrecy and binding, tenant isolation, revocation, request identity/replay protection and honest readback. A caller-selected expected head remains an accuracy check. Missing transaction storage or an unverifiable outcome must never be represented as success.

## Explicit delegation

Read-only connections and deliberately limited profiles/passes remain limited. A delegate cannot assert owner status to widen its grant. Existing issued pass allowances, repositories, areas, access permissions and expiry stay effective. Changing the owner's standing preferences does not rewrite previously issued grants. No migration silently expands a pass.

## Builder scope

Implementation agents follow AGENTS.md: no autonomous purchases, no unapproved real destructive tests, fake/disposable fixtures, required code review and exact-head CI, and the builder release policy. Those are engineering operating instructions, never shipped restrictions on full owner connections. The owner can explicitly direct a departure from their own process defaults; service credentials and platform permissions remain required.

## Fallback requirement

When exact parity is unavailable, build the strongest practical Robinson AI Systems alternative. If the MCP cannot supply the operation, its result must provide concrete repository setup instructions, configuration, verification and the remaining limitations. A heuristic scan, existing-alert read or guide must never be reported as execution of GitHub's proprietary fresh-content scanner.

## Implementation truth

The current remediation changes the common owner write lifecycle and selected tool-specific paths. It does not certify every legacy connection/setup page, universal operation or old acceptance row. The plan records unresolved surfaces and release-dependent checks. Source tests, merge, deployment and real-client acceptance are separate evidence.

Earlier dated audit conclusions, including claims that the authority audit was already complete, are retained only in [the historical record](archive/END-USER-AUTHORITY-before-20261028.md). They do not override current requirements or prove current live behavior.
