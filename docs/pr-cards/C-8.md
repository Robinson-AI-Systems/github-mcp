# C-8 — Remove avoidable single-call overhead without weakening GitHub MCP

**Authorization:** owner feedback 2026-10-27: agent measured a simple custom check ~2.8 s vs official ~1.3 s, with large workflow-level improvements from C-3..C-6 that must not regress. **Status: IN_PROGRESS.** Depends on C-5/C-6, provider-parity PR #423. No new credentials, subscription, publishing, production release, plan or API permissions.

## Drift check (measure before code)

- Three alternating authenticated `whoami` calls from one ChatGPT connector session measured official 326/362/338 ms and custom 1172/724/617 ms (different implementations/connections, small sample; **not** a controlled provider benchmark and not evidence that every call is slower).
- `src/tools/server.js` `github_whoami` serially requests per-account rate state; separately reads master status and then `actAsFor` reads it again; in `src/github/act-as.js` three independent settings and one rate read happen serially, followed by an optional duplicate personal-rate query.
- `src/tenancy/runtime-limits.js` `withTenantProviderMetrics` synchronously awaits an isolated Postgres metrics upsert in each GitHub HTTP fetch's `finally`. This makes telemetry DB latency extend provider read critical paths. The tenant HTTP route already has a guaranteed `finally` checkpoint in `api/mcp.js`. Metrics must still be recorded per provider request with the same tenant, outcome, and coarse latency bucket (no URL/content/secrets), and its last flush must be awaited before handler completion.
- Do **not** change per-call bearer validation, tenant admission and quota checks, GitHub read/write rate limiting, authenticated provider result/error, request journal or production gates. No stale reusable cache for CI/permissions.

## Complete acceptance criteria

1. [ ] `github_whoami` retains exactly the current observable fields, connection/profile/account filtering, master expiry and Act-as-me/rate semantics. Independently read-only per-account rates execute concurrently (bounded by max 10 authorized accounts); master status is obtained once; Act-as-me independent setting reads overlap; no duplicate personal rate read. Tests prove output, scope and concurrency with deliberately delayed database reads.
2. [ ] Tenant GitHub provider telemetry no longer stalls **each** provider reply on Postgres writes. Record per-call success/refusal/error and duration bucket in a bounded *per-request* buffer; coalesce to a single scoped PostgreSQL flush alongside the MCP event in the route `finally`, awaited even on refusal/errors. No shared global state, no raw provider metadata, no loss of event counts, no effect on outcome if telemetry fails, and existing auth/admission/usage limits unchanged. Non-MCP callers continue their existing semantics. Real isolated database regression proves counts, cross-tenant isolation and failure/cleanup behavior.
3. [ ] Deterministic artificial-delay benchmarks show the critical-path reduction for the independent `whoami` reads and provider metric persistence, while retaining complete provider result readback. Do not extrapolate synthetic numbers into real production speed.

## No-go boundaries

No fire-and-forget persistence, silent skipping of provider metrics, changes to personal/tenant token validation or credential refresh, weaker GitHub permissions, bypassing release gates, paid services or direct changes to `main`/`live`.
