## Acceptance before implementation
- [ ] File content that is truncated for the first response is **durably kept**, under an account/connection-scoped handle that `github_get_result` can successfully read until expiry; no false `could not be kept` on the supported fixture.
- [ ] Existing 8 KiB initial-result cap is preserved; an explicitly requested second handle read delivers the rest of a 25 KiB file in one request, byte-exact (UTF-8 multibyte and minified single-line cases).
- [ ] Add `byteOffset` and `byteLength` (or documented equivalent) so callers can directly read reproducible byte ranges; make byte encoding explicit, reject invalid ranges, and preserve existing line-range semantics and errors.
- [ ] Cross-account/tenant handle retrieval is refused; absent/expired/oversized/unavailable storage produces an explicit recoverable error rather than claiming success. No GitHub credential is exposed.
- [ ] Source unit and database tests demonstrate 25 KB in ≤2 calls, handle paging, binary/multibyte/minified edge cases, failures and scoping. Run focused suites then CI exact-head `ci` and `release-policy`.
- [ ] Add changed-tool docs/ROADMAP/work-index/status as required; perform full diff self-review; merge only at exact green HEAD. **Close #427 only after merge and acceptance proof.**
