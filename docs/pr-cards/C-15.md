# C-15 — Accurate credential-specific observed GitHub rate metadata (#435)

**Approval:** Owner-requested 2026-10-27 issue #435, separated from C-13 because rate-identity and response dispatch are a distinct cross-credential infrastructure boundary. Do not retrofit #435 as completed in PR #440.

## Acceptance criteria — record before coding

- [ ] Bounded, trustworthy rate meta attaches to final responses for reads, writes, nested workflows and failures, only after this *request's* observed GitHub headers or explicitly labelled current, matching persisted observation; include resource, credential/account identity, remaining where actually observed, reset time, and primary/secondary cooldown without inventing missing quotas.
- [ ] Distinguish app installation, personal Act-as-me, named user, God Mode/master, package and notifications credentials. Share neither quota nor stale cache between those classes, accounts or connection tenants. Scoped metadata is only for the authenticated allowed account; do not expose any raw token, private subject ID or secret.
- [ ] Record actual response headers once at the existing GitHub client hook, including throttled error responses, 304 conditional reads and cross-nested calls. Handle concurrency without wrongly labelling old values fresh; no new GitHub API calls just for observability and no disruption to existing write pacing, retry or limits.
- [ ] The canonical dispatcher supplies compact safe metadata consistently and preserves success/error envelopes, read-field selection, retained results, RTC/API and `github_call` behavior.
- [ ] Table-driven tests cover core/search/graphql, 403/429 secondary/primary, reset windows and absent headers, multi-credential, nested, parallel, failure and tenant boundaries, plus disposable-Postgres behavior where persistence and isolation are affected.
- [ ] Update source, tests, catalog, decisions, roadmap/status/index and dated status note; validate focused/full suites and required exact-head `ci` and `release-policy`; close #435 only after reviewed merge and independent readback. No production release/credential change.

## Initial source map

`src/github/rate.js::recordRate` already parses provider rate headers and persists via `db.recordRateState`. `src/github/client.js::githubFor` selects the actual credential per request; its current `rateKey` is not distinct for all credential kinds. `src/tools/dispatch.js` has the shared top-level/nested response envelope. Reuse those, isolate identity correctly, and keep network requests unchanged.
