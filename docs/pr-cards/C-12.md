# C-12 — Never duplicate large read bodies across MCP content and structuredContent (#428)

**Owner authorization:** issue #428 coding-agent field feedback 2026-10-27; user asked to work through all issues. **Purpose:** stop doubling token/payload cost while keeping every byte reachable, through direct, catalogue, batch and RTC paths.

## Drift check A

| Assumption | Actual behavior on main | Proposed response |
| --- | --- | --- |
| Large text is returned once | `readReply` serializes one body into both text `content` and `structuredContent` | For fat results retain full canonical JSON in text content, and use scalar/computed lightweight structured metadata with an explicit full-text pointer |
| Catalogue calls can still access all details | `github_call` forwards the delegate envelope; `github_batch` takes only `structuredContent` | Forward full text intact; batch must reconstruct full authorized data before applying its own result budget |
| Describe tool schema is cheap | `github_describe_tool` returns the schema in both channels | Full schema only in content, structured carries name, kind, area and compact state |
| Small payload backward compatibility | Small whoami/actions results are fully duplicated today | Keep the old dual-copy shape for small results; document exact threshold and the opt-in lossless content parsing contract for larger ones |

## Acceptance (write before implementation)
- [ ] Representative large PR body and tool schema are sent only once in full, in `content`; structured has bounded scalars and computed fields and an explicit notice of where the full payload lives.
- [ ] Direct read, github_call, github_batch and RTC/HTTPS transport retain lossless access to every authorized field, including result handles, offsets, paging, security annotations, and error shapes.
- [ ] Real compressed/encoded byte windows from C-10 remain byte-exact when read via text JSON. No hidden second full copy in another channel.
- [ ] Large responses shrink near 50% in common fixtures, while small replies preserve existing callers. Tests cover untrusted/restricted responses, secret redaction, no accidental credential leaks, double-submit/write journal unaffected.
- [ ] Full CI `ci` plus `release-policy` green on exact head; all review threads resolved; merge and independently verify #428 closed before claiming completion.
