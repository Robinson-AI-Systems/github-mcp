## Acceptance criteria BEFORE source implementation
- [ ] New read-only `github_content_snapshot` receives account/repository/ref and pins a single authoritative commit SHA, even if the branch moves; downloads once via existing redirect trust/ZIP code; retains bytes in existing per-connection result storage, returning a handle, byte length, ZIP SHA-256, complete=false, expiry and clear retrieve instructions. No source ZIP or signed URL is accidentally sent inline.
- [ ] `github_get_result({handle, byteOffset, byteLength})` returns exact base64 bytes from retained ZIP with original digest, byte offsets/length/total/next/EOF. A small multi-file fixture with unusual UTF-8 paths and binary entries is transferred in **≤3 MCP calls**, then unzips byte-for-byte; reject cross-account handles, expired data, corrupt ZIP, missing redirect, oversized archives, stale refs and credential-shaped repository contents. No extra archive provider call for continuation.
- [ ] `fields` works consistently through direct tools, `github_call`, `github_batch`, universal REST/GraphQL reads, RTC and kept-result paging, using dotted paths. Requested fields are included and others excluded, while mandatory IDs, continuation handles, error/untrusted markers and companion timestamps survive. Unknown fields are explicitly surfaced and no hidden full fallback is emitted.
- [ ] Read, write and rate-limited replies may include **bounded** rate metadata when known from the current request's *actual credential/account/resource* headers: remaining, reset time, secondary cooldown, fresh-vs-cached. Unknown is omitted, not invented; never use app budget for a personal credential or leak another tenant's observation. No extra GitHub requests solely to populate metadata.
- [ ] Table-driven fixtures cover core vs search/graphql buckets, app vs personal, concurrent calls, primary and secondary throttles, source unavailability, rate resets, no-rate headers, nested/cross-tenant calls and malformed selectors, including fake + disposable PostgreSQL where persistence matters.
- [ ] Byte cap and token-saving defaults remain efficient, but an explicitly authorized user can recover **all valid bounded source data exactly**; credential scanning, OAuth/tenant, untrusted content, production/spend and write-contract boundaries unchanged.
- [ ] Update tool catalog, design, decisions, roadmap, status, index and validator together; run focused suites first, full suite **once on finished bundle**, exact-head `ci` and `release-policy`, resolve all review threads; merge and read back **each** of #430/#435/#436 as closed/completed. Never claim a deployed client was exercised unless separately verified.

## Implementation boundaries
Provider reads remain pinned through `src/github/client.js`; public ZIP redirects via `downloadPublicAsset`. No new external provider, paid services, indefinite poller, production setting or user credential. Avoid leaking signed URLs. Cap in-memory/archive retention to existing ZIP-reader resource budgets; errors must be explicit rather than fake successful handles. Archive status is exact SHA, not an unverified branch label.
