# 2026-11-03 — Push exit near GitHub (PUSH-EXIT-1)

Owner direction (relayed): make big git pushes from an agent sandbox fast, through a replaceable "push exit".

Measured and proven live before building (temporary Dokploy probe compose, deleted afterwards): Dokploy's Traefik HTTP
route cuts uploads at 61 s; a Traefik **TCP** route (SNI passthrough, PROXY v2) to a Caddy front door carried a 97 s
upload and a 95–100 s download intact and 150 MB in 75 s. Sandbox → Dokploy upload is ~2.2 MB/s and parallel streams do
not add up, so Dokploy's inbound link is the limit (Cloudflare sink: 10.7 MB/s from the same sandbox). Approach A chosen;
details and numbers in the card.

Built: `GIT_DIRECT_HOST` picks the pool host serving `GIT_DIRECT_ORIGIN` (unset = primary, as before); setup places every
allowed caller's key there first (`push_exit` in the result, plain `direct_note` fallback), op=authorize and
`github_server_status` (`direct_git.exit`) follow it; the worker compose gains the `push-exit` Caddy service behind a
Traefik TCP passthrough router. Card: [PUSH-EXIT-1](../pr-cards/PUSH-EXIT-1.md).

Verified here: `tests/unit/push-exit.test.js` and the existing git-remote, git-direct, git-direct-configure, worker-pool,
worker-pool-owner-hosts and server-status suites; `npm run check`. The shipped Caddyfile was run live on the probe.
Not verified: the real worker behind the front door and pushes to GitHub through it (needs Chris's release, the Dokploy
redeploy and the two Vercel values in the card's Release section).

Next (after release): Dokploy redeploy, Vercel `GIT_DIRECT_ORIGIN=https://git.robinsonaisystems.com` +
`GIT_DIRECT_HOST=previous`, one setup, then 40 MB / 150 MB / ~1 GB timings on robinson-ai-scratch/upload-probe.
