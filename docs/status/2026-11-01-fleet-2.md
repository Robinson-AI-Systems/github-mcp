# 2026-11-01 — FLEET-2 faster small runtimes

**Merged (PR #518):** slim runtime image gate, `github_playground_run` (run-at-commit), out-of-memory upsize hint.

- Small jobs whose repository shows no browser/database signals get the `<sha>-slim` image (no Chromium/PostgreSQL);
  everything else, or anything unreadable, gets the full image. Missing slim → full → source build. The choice and its
  reason are stored on the allocation and shown by `github_playground_read allocation`.
- `github_playground_run` runs one command at a branch/tag/SHA and cleans up; each call works ~40 s and a repeat call
  with the same requestKey continues.
- A kernel OOM kill is reported as `reason: out_of_memory` with the next size up.

Verified: focused vitest files (`playground-run`, `playground-runtime-variant`, `playground-oom` and existing
playground/fleet/native suites), `npm run check` on the final tree, exact-head CI. The real slim image build and the
real cgroup OOM smoke run in the PR's "Coding workspace image" workflow (no local Docker daemon).

Not done / next: the first `<sha>-slim` tag appears on the next release's publish run; live acceptance of
`github_playground_run` against the deployed server is queued (needs a release and a runtime host). FLEET-7 (warm
runtimes) is next and depends on this.
