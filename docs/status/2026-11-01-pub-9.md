# 2026-11-01 — PUB-9 fine-grained token tenants

- Built: a signed-in person can add a GitHub fine-grained token on the protected one-use page (My connection → "Add a
  fine-grained token"). The server checks it with GitHub (same person, fine-grained, not expired, one owner), reads which
  repositories it reaches and what it can read, stores it encrypted (vault kind `F`) and opens that owner as a read-only
  extra place. Re-check, Remove and the changes switch are on My connection.
- Gate: tool listings never change; `github_whoami` mentions fine-grained tokens only after one is added. Requests on its
  place are checked before GitHub against GitHub's published permission list and the recorded permissions; a missing one is
  refused with plain guidance. The App and the person's sign-in still come first; read-only connections and passes never use it.
- Verified: unit, shape (pinned schema), real PostgreSQL and real-browser (phone size) tests; see the PUB-9 card.
- Not done: real-account check (optional owner checklist row; needs a release first). Write permissions are learned from
  GitHub's refusals because GitHub does not show them.
