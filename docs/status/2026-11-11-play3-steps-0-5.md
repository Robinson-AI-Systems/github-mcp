## Steps 3–4 — provisioning + bootstrapper: IMPLEMENTED, logic bench-verified; Windows dry-run partial

- `provision/`: cloud-init user data + idempotent `apply-provisioning.sh` (worker account locked,
  Docker Engine + Compose v2 via `docker.io`, Node 22 via NodeSource, unattended security
  updates); `merge-wslconfig.mjs` (respects existing keys, preserves unknown sections, refuses
  unparsable files); `provision-distro.ps1` — **deviation from the design's shorthand, recorded:**
  the distro is created with `wsl --import` from the official Ubuntu WSL rootfs (a custom distro
  name is impossible with `wsl --install`); the image SHA-256 is a release input, verified before
  import, and an unpinned build refuses to import. Every `wsl.exe` call has a hard timeout.
- `setup/`: `preflight.mjs` (canonical F1–F14 classification, unit-tested), `Setup.psm1` /
  `setup.ps1` (journal-resumable bootstrapper; ONE elevation batch whose contents are data —
  `Get-ElevationBatch` — so the single-UAC audit is a read, not a trace; keeper + resume tasks;
  reboot gate; pairing-file join; pause/remove with feature restore from the journal; `-Plan`
  dry-run), `pages/` (download, pairing, one page per detour). The PowerShell classifier mirrors
  `preflight.mjs` (a target PC may have no Node) and is held to the same fixtures.
- Bench run `play3-pr2-verify` (PC bench WSL): `play3-provision.test.js` 12/12 pass. The
  PowerShell files were audited by hand (AST-level read; four defects found and fixed, incl. a
  payload-copy quoting bug). A live Windows-side `-Plan` dry-run is **not yet run** — declared
