# 2026-11-01 — FLEET-7 warm runtimes (gated)

- **What changed:** warm runtimes exist as code, used only when their gate says so. A warm runtime is a tiny tenant-free
  "image holder" that keeps the exact runtime image on a pool's host so new runtimes skip the image download. It holds no
  workspace, connection, tenant or credential; every workspace still gets its own fresh single-use runtime.
- **Design:** option (a) warm image. Option (b) (pre-started runtime with a late signed bind) was rejected: today's
  isolation, ownership and cleanup checks are keyed on the binding baked into every name, label, volume, network and
  environment value, and a late bind would need new, weaker trust paths. Reasons in `docs/pr-cards/FLEET-7.md`.
- **Gate:** per pool, on only when new runtimes per hour over the last 24 h ≥ 6 **and** a fresh (≤ 60 s) host reading
  shows ≥ 8 GiB memory, ≥ 50 GB disk free and pressure ≤ 0.5. Sized from demand (≤ 2 images), capped by disk headroom.
  The cleanup sweep drains holders when demand falls, headroom shrinks, the reading goes stale or
  `PLAYGROUND_WARM_RUNTIMES=off`.
- **Today:** off (a handful of runtimes a day; no capacity feed). Visible in `github_playground_read` `capabilities` /
  `availability` without a workspace (`warm_runtimes.reason`).
- **Verified:** `tests/unit/playground-warm-runtimes.test.js` (20 tests), `tests/db/settings.test.js` on local Postgres,
  all Playground/fleet unit tests, `npm run check`.
- **Not done:** no live start-time measurement (needs real demand). No owner action needed.
